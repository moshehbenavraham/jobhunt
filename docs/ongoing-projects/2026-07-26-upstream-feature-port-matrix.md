# 2026-07-26 Upstream Feature Port Matrix

## Objective

Port every relevant capability introduced between the upstream fork point
`2051bebc2f8113673e0b79f7dea68b0a574d9930` and snapshot
`adc04fb0586e5b50d9d2dbacea3526f90c2174f3`, improving each adopted capability
for this fork's path layout, user-data contract, validated PDF contract, and
Codex-first runtime.

The evidence bundle is:

- `EXAMPLE/UPSTREAM-DIFF-REPORT.md`
- `EXAMPLE/upstream-at-fork/`
- `EXAMPLE/upstream-latest/`
- `EXAMPLE/upstream-diff-evidence/`

The current fork worktree is authoritative for implementation status. A file
with a similar name is not proof of parity.

## Completion rule

The port is complete only when every `Required` or `Relevant` row below is
`Proven`, its acceptance evidence exists in the current worktree, and the full
validation suite passes. `Deferred` is a priority label, not removal from
scope.

Status meanings:

- `Proven` -- current implementation and tests cover the stated acceptance
  contract.
- `Partial` -- useful behavior exists, but material upstream behavior or
  verification is missing.
- `Missing` -- no equivalent implementation exists.
- `Excluded` -- intentionally not relevant to this fork, with a documented
  reason.

## Fork invariants

Every port must preserve these stronger local contracts:

1. Canonical user paths remain under `profile/`, `config/`, `data/`,
   `reports/`, `output/`, `jds/`, and `interview-prep/`.
2. No updater may modify a user-layer artifact.
3. Applications are never submitted and messages are never sent by the
   workflow.
4. New tracker rows flow through TSV additions; existing rows may be updated by
   canonical maintenance tools.
5. A tracker PDF is present only when its sibling manifest is fresh and records
   `validation.valid: true`.
6. Ported network and filesystem behavior must add containment, sanitization,
   timeout, and regression coverage rather than copying unsafe assumptions.
7. The fork remains Codex-first until the single-user app parity project is
   proven complete.

## Explicit exclusions

These upstream changes are not runtime features to port:

- manifesto/signature bots and public advocacy ledgers
- press logos, launch assets, and README translation count as a goal by itself
- upstream maintainer/contributor rosters and trademark governance
- Claude/OpenCode/Qwen/Kimi/Grok wrappers and the npm scaffolder while this fork
  remains intentionally Codex-first
- upstream flat-root path layout and root user files
- upstream PDF behavior where it is weaker than the fork's validated sibling
  manifest contract
- deletion of any existing user-owned story bank or other user artifact
- upstream alpha web source as a wholesale copy; the fork's existing app parity
  PRD is the authoritative target

## Delivery order

1. Shared tracker parser, writer lock, status transition, reservation, and
   reconciliation.
2. Shared network/path safety and updater structural coverage.
3. Provider registry, scanner capabilities, trust/health ledgers, and filters.
4. Machine summaries, risk normalization, and evaluation harness.
5. Lifecycle communication/application tools.
6. Interview/offer/analytics tools.
7. Dashboard parity and tracked single-user application.
8. Optional runners, hardened plugins, containers, and additional locales.

Cover-letter support was completed first because it was an already documented
gap with a self-contained end-to-end acceptance contract. It does not change
the remaining delivery order.
